# Tech Debt — simtools

Module is **1 monolithic file (2064 lines)** containing: IX PRT parser, 3 rel-perm families, 3 rel-perm table builders, LET physicality check, fitter(s), Van Everdingen-Hurst influence tables, Rachford-Rice solver, VFP formatter + builder (prod & inj), BOT builder (delegating), PVTW builder, and a zip/check deck walker. No sub-files.

## High

- **`rr_solver` duplicated verbatim with brine/_lib_vle_engine.py's `rr_solver`.** simtools.py:1017–1116 and brine/_lib_vle_engine.py:1011–1107 implement Nielsen & Lia (2022) with the same equation references ("Eq 10", "Eq 11a", "Eq 12b", "Eq 16b", "Eq 27b", "Eq 28"), the same logic, and the same structure. The brine copy is the better one (has singularity perturbation at `K=1`, `warnings.warn` on non-convergence, configurable `tol`/`max_iter`, explicit single-phase wrapper `solve_rachford_rice`). simtools copy has neither the K=1 guard nor the convergence warning — both are the *correctness bugs* already flagged in the correctness review. Fix by making simtools `rr_solver` a thin re-export from `brine._lib_vle_engine`.

- **`ensure_numpy_array` (simtools.py:1009) duplicates `shared_fns.convert_to_numpy`.** The shared helper is already imported across gas/dca/brine. simtools should call `convert_to_numpy` instead of a local copy. Bonus: drop the implicit public export (it has no leading underscore, not in `__all__`, but leaks via `simtools.*`).

- **VFP `_format_vfpinj` / `_format_vfpprod` share a large prologue** (simtools.py:1123–1164 vs 1167–1236): both compute unit strings, write `Generated by pyResToolbox ...` banner, format completion segments, and format flow/THP axis records in identical ways. Extract `_format_vfp_header(completion, datum_depth, flo_type, flo_rates, thp_values, unit_system, writer_name)` plus `_format_axis_line(values)` helpers. Currently ~60 lines of near-duplication.

- **`make_vfpinj` and `make_vfpprod` share ~50 lines of metric conversion / default-value / n_failed-printing scaffold** (simtools.py:1302–1342 vs 1517–1596 and again 1384–1417 vs 1648–1712). Both loops catch exceptions and write `1e-6` + `print("Warning: ...")`. Should share a `_to_oilfield_vfp_inputs()` / `_to_metric_vfp_outputs()` helper, and a common `_record_failure(bhp_array, idx)` writer. Both also use a hard-coded `1e-6` sentinel for failed cells — magic number.

- **Rel-perm table section has 3 near-identical blocks** (SWOF, SGOF, SGWFN; simtools.py:486–581): each (a) computes `ndiv` with table-specific decrements, (b) builds `sw/sg` saturation array plus epsilons, (c) calls `_apply_kr_model` twice for the two kr columns with appropriate normalization windows, (d) packages DataFrame with column-name triples, (e) optionally writes `<NAME>.INC`. Lift into `_build_kr_axis(endpoints, rows)` + `_build_kr_pair(sn, ...)` + `_write_incfile(name, headers, df)`. ~90 lines of structurally-identical code.

## Medium

- **File-write scaffold has no common writer.** 5 places write INC files (`SWOF.INC`, `SGOF.INC`, `SGWFN.INC`, `INFLUENCE.INC`, `PVTW.INC` at simtools.py:516/547/579/814/2013) + 2 more in `oil/_tables.py` (PVDG/PVDO/PVTO). Plus `make_vfpinj`/`make_vfpprod` writes `VFPINJ_N.VFP` / `VFPPROD_N.VFP`. All write to `os.getcwd()` with no `dir=` option, no returned `written_path`. A single `_write_keyword_file(name, text, filename=None)` helper that optionally logs + returns the absolute path would kill the duplication and fix the API/UX gap simultaneously.

- **Magic numbers not extracted to named constants**:
  - `EPS_T = 1e-15` (line 92) and `MAX_ITR = 100` are used only by `rr_solver`; if that is delegated to brine, they become dead.
  - `1e-30` denominator guard in `LET` (line 285), `jerauld` (line 320), `fit_rel_perm` (line 638). Should be a single named `_KR_DENOM_FLOOR = 1e-30`.
  - `1e-10` used as both `jerauld b` floor (line 317), `LET monotonicity tolerance` (line 339), and RR-solver `ki_hat==1` threshold (line 1070) — three independent meanings for the same value.
  - `1e-6` sentinel for failed VFP cells (lines 1378, 1642) — should be `_VFP_FAILED_BHP_PLACEHOLDER`.
  - `0.5` in `rr(0.5)` (line 1063) as "midpoint check" — comment-worthy but not a magic number per se.
  - `2.0`, `1.0`, `20.0`, `50.0`, `100.0` as `fit_rel_perm` bounds/x0 (lines 646–658) — named `_COR_X0`, `_COR_BOUNDS`, etc. Not critical.

- **Unused imports**:
  - `import os` (line 55) — never referenced.
  - `import pyrestoolbox.gas as gas` (line 87) — never referenced. Dead.
  - `vlp_method` from classes (line 69) — imported, never referenced in annotations or code (VFP uses `str` + `validate_methods`).
  - `uo_method` from classes (line 71) — imported, never used.
  - `MMSCF_TO_SM3`, `MSCF_TO_SM3`, `SM3_TO_MSCF`, `SM3_PER_SM3_TO_STB_PER_MSCF`, `STB_PER_MMSCF_TO_SM3_PER_SM3`, `SM3_PER_SM3_TO_STB_PER_MMSCF`, `KGM3_TO_LBCUFT`, `INVBAR_TO_INVPSI` — imported from constants, never used.
  - `temp_unit` assigned but never read in both `_format_vfpinj` (line 1130) and `_format_vfpprod` (line 1176). Dead variable.
  - `pb_unit`, `rsb_unit` computed in `_format_vfpprod` (lines 1189–1190) but only one of them is used on the optional PB/RSB line — verify both actually reach output.

- **Monolith — no sub-file split.** At 2064 lines covering 7+ independent concerns, this file is the same size as oil was before v3.1.4's split into `_correlations`, `_density`, `_compressibility`, `_rate`, etc. Suggested split:
  - `_relperm.py` (Corey/LET/Jerauld + fit + physicality + `rel_perm_table`) ~ 450 lines
  - `_vfp.py` (`_format_vfpinj`, `_format_vfpprod`, `make_vfpinj`, `make_vfpprod`) ~ 600 lines
  - `_influence.py` (Van Everdingen-Hurst AQUTAB) ~ 100 lines
  - `_rr.py` (or import-only shim re-exporting from brine) ~ 20 lines
  - `_deck.py` (`ix_extract_problem_cells`, `zip_check_sim_deck`) ~ 300 lines
  - Keep `simtools.py` as the thin re-export surface.
  - `make_bot_og` and `make_pvtw_table` are already thin wrappers to oil/brine — leave them at the top level.

- **`_apply_kr_model` uses `if fname == "COR"` string-dispatch** (simtools.py:367–374). Enum-value dispatch would be cleaner; `kr_family` is already an Enum. Trivial cleanup.

- **`_resolve_pb_rsb` / `_build_bot_tables` / `_format_bot_results` accessed via `_oil_impl._resolve_pb_rsb`** with a separate alias `import pyrestoolbox.oil as _oil_impl` vs `import pyrestoolbox.oil as oil`. Two aliases for the same module — consolidate. (simtools.py:89–90)

- **Type hint gaps**:
  - `zip_check_sim_deck(files2scrape = [], tozip = True, console_summary = True)` — no hints, no return type. Mutable default `[]` for `files2scrape` is a Python antipattern.
  - `ensure_numpy_array(data)` — no hints.
  - `_format_vfpinj(...)` and `_format_vfpprod(...)` — fully untyped despite being internal helpers the IDE users will inspect.
  - `make_bot_og` returns `dict` but docstring describes a 10-key payload that could be a `TypedDict` (non-critical).

## Low

- **`influence_tables` Python fallback prints `"Calculating ReD = X"`** on every ReD (line 768). The Rust fast path is silent. Inconsistent. Should honor a `silent` kwarg (or just drop the print — the inverse Laplace takes ~5 s and the user already knows they're waiting).

- **`ix_extract_problem_cells` reads `*.PRT` but uses `glob` without case-insensitive matching.** Linux deployments with lowercase `.prt` miss files. (`zip_check_sim_deck` handles this with upper+lower double-glob; `ix_extract_problem_cells` does not — inconsistent.)

- **`most_frequent` nested function** (line 220) could be `_most_frequent(items)` at module level so it's testable.

- **`get_loc` nested function inside `zip_check_sim_deck`** (line 837) is 33 lines with its own `input()` prompt. Would be a cleaner module-private helper.

- **`rel_perm_table` export block is triplicated** (lines 512–517, 543–548, 575–580): `df.set_index("Sw")` / `tabulate(df, headings)` / `open(...).write(fileout)`. Extract `_write_kr_inc(df, keyword_name, headers, index_col)`.

- **`_normalize_saturation` silently returns `np.zeros_like(s_actual)`** when `span <= 0` (line 351). This is flagged in the correctness review; from a tech-debt angle the helper has no input validation and no tests for edge cases.

- **`fit_rel_perm` redundantly computes `kr_pred = krmax * (result.fun + kr_scaled)`** (line 666) instead of re-evaluating the fitted model at the sample points. Works, but depends on the definition of residuals — fragile if anyone changes the residual direction.

- **`make_pvtw_table` builds a pressure grid that may not contain `pi`** (line 1963–1966); uses `list(np.linspace(...))` then appends `pi`. A helper `_pressure_grid_with_anchor(pmin, pmax, nrows, anchors)` is also needed by `make_bot_og` (line 1851–1857). Duplication.

- **`from ilt import gwr`** is only used in the Python fallback branch of `influence_tables` (line 769). Consider a local import so environments without `ilt` installed don't fail module-load — though `ilt-inversion` is a listed dependency, so the cost is minor.

- **Tier 2 rule (`/home/mark/projects/pyResToolbox/.claude/rules/simtools-module.md`) references `deck_check` but the function is named `zip_check_sim_deck`**. Stale rule. (Already flagged in API/UX review — repeating here because it's tech debt on the docs side.)

- **`__all__` in `simtools/__init__.py`** is `from .simtools import *` which propagates `ensure_numpy_array`, `EPS_T`, `MAX_ITR`, `tabulate`, `gwr`, `Counter`, `mp`, `zipfile`, etc. Public surface is polluted. Should rely on `simtools.__all__` (which IS defined at line 44 of simtools.py). Verify Python's `import *` semantics honour the `__all__` declaration in `simtools.py` — it does, but the re-export in `__init__.py` is noisy and makes introspection harder.

- **`LET()` clip range `[0.0, 1.0]`** (line 286) silently caps unphysical values instead of flagging them. `is_let_physical` exists specifically to catch these but isn't auto-invoked by `LET`. Tech debt in API composition.

- **`corey()` returns a single expression `s ** n`** — fine, but has no input range validation or clip guard, inconsistent with `LET`/`jerauld` which both clip to `[0, 1]`.

## Test Coverage Gaps

31 tests in `test_simtools.py`:
- **No tests for `zip_check_sim_deck`**, `ix_extract_problem_cells`, or `influence_tables`. Three of the largest functions in the module are untested.
- **No `make_bot_og` tests** (oil-module tests may cover the underlying logic, but the simtools entry-point wiring is untested).
- **No `make_pvtw_table` tests** (same: brine coverage may overlap but simtools-level integration is not verified).
- **VFP tests cover happy paths** (gas basic, oil basic, monotonic BHP) but no metric-mode tests, no low-rate fallback tests, no `n_failed` assertion tests, no `export=True` file-write tests.
- **RR solver has 4 tests** but none triggers the `max(ki) >= 1.0` edge case (the flagged correctness bug). A reproducer test would belong here.
- **No `fit_rel_perm` error-case tests** (empty arrays, mismatched lengths, single-point fit).

## Rust Parity

- **`influence_tables` has Rust (`src/gwr.rs:515`) and Python paths.** Both converge on the same Van Everdingen-Hurst Bessel/GWR integration. Algorithmic drift risk is low (no recent changes), but the Python path has the `denominator → 0` NaN-prone branch (correctness review line 27) that the Rust path handles more cleanly through `mpfr` precision. Mismatch is cosmetic for most inputs but will diverge at extreme `ReD`/`td`.
- **`rr_solver` has NO Rust counterpart in simtools** (brine's `flash_tp` in `src/vle/flash.rs` uses its own RR internally). If simtools' `rr_solver` is retired in favour of `brine._lib_vle_engine.rr_solver`, there's nothing to port.
