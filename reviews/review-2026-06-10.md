Six parallel domain agents (gas, oil, brine/VLE, nodal, analytics, infrastructure) over the current main branch, followed by an orchestrator verification pass. Every High finding below was either reproduced numerically by the orchestrator from the repo package, or confirmed by direct code read plus dimensional/algebraic derivation. Agent-only verifications are marked. Known false positives from the 2026-04-17 review were excluded from agent scopes and none were re-flagged.

All 838 tests pass on current main. Every bug below sits in untested territory; several are pinned as correct by frozen baselines or doc-example tests, so fixes need explicit approval before baselines move.

## Part A - Technical errors

### High severity

**A1. `gas_rate_linear` over-predicts by exactly 2 pi** - `pyrestoolbox/gas/gas.py:510-515`
`darcy_gas` reuses `_DARCY_GAS_CONST = 1422` (the radial constant, which embeds the 2 pi of radial geometry) in the linear branch. The linear-flow constant must be 2 pi x 1422 ~ 8934 (derivable from the pi-vs-one-half geometry factors in the radial and linear pseudopressure solutions). Reproduced: k=0.1 md, A=50 ft2, L=200 ft, 180 F, sg 0.8, 2000/250 psia gives 8.202 Mscf/d vs 1.305 first-principles; ratio 6.286 = 2 pi. The same derivation reproduces `gas_rate_radial` to 0.04%. Frozen baseline `test_gas.py` and doc examples pin the wrong values.

**A2. Hall-Yarborough Z solver performs exactly one Newton step, always** - `gas.py:917-931` and `src/zfactor/mod.rs:108-132`
Loop tail sets `yi = y`, so the top-of-loop convergence test always sees zero error on the next pass and breaks. HY output is "WYW guess + one Newton step", never the converged root. Reproduced vs brentq on the HY equation: z error 13.9% at Tpr 1.05 / Ppr 2, 4.2% at Tpr 1.05 / Ppr 4, <0.5% mid-range. Long-standing (the original scalar loop had the same flaw). Fix in Python and Rust together.

**A3. Motiee hydrate temperature ~30 F too high** - `gas/_hydrate.py:23, 171-188`
Code evaluates the coefficient set in kPa / degC space; the widely published fit is psia / degF (and the intercept -283.24469 vs -238.24469 is itself suspect: the -238 psia/degF form lands near the Katz chart, the coded form does not). Reproduced: 1000 psia, sg 0.6 gives Motiee HFT 91.3 F vs Towler 61.1 F (Katz chart ~62-66 F). `hydmethod='MOTIEE'` badly overpredicts HFT and overstates inhibitor dose; default TOWLER unaffected. Confirm the original Motiee (1991) paper before fixing. Frozen baseline pins the buggy value.

**A4. Petrosky-Farshad undersaturated viscosity uses ln instead of log10** - `oil/_correlations.py:481`
McCain Eq 3.24b defines X = log10(uob); code uses `np.log(uob)`. Reproduced: api 45, 250 F, pb 2000, rs 800 (uob 0.254 cP) gives 1.53 cP at 8000 psia vs 0.40 cP with log10 - a 6x unphysical viscosity rise over 6000 psi. Frozen baselines are all at p <= pb so are not touched; PVTO undersaturated viscosities change.

**A5. `oil_rs_st` returns ln(Rst), the exponential is missing** - `oil/_separator.py:103-107`
Valko-McCain 2003 Eq 3-2 is ln(Rst) = polynomial; the code returns the polynomial directly. Reproduced: psp 114.7, 80 F, api 38 returns 4.18 scf/stb; exp(4.18) = 65, consistent with the docstring's own 0.1618 x Rsp heuristic. Output ~15x too low. Also: metric output is never converted back. Doc example pins the buggy value. Confirm Eq 3-2 against the paper before fixing.

**A6. Vogel IPR wrong for undersaturated and saturated edge cases** - `oil/_rate.py:88-89, 104-108, 179-191`
The `pb = max(pb, pwf)` clamp only applies when `pwf.size > 1` in `oil_rate_radial` and never in `oil_rate_linear`. Reproduced: scalar pwf 3000 > pb 2000 gives 1477 stb/d vs 1899 from the array path / pure Darcy (22% low). Neither function handles pr < pb (returns negative rates at pwf = pr). When `oil_pvt` is supplied, `vogel=True` is forced, so users hit this silently.

**A7. Python/Rust divergence in oil density above Pb corrupts `oil_co` on Rust wheels** - `src/oil/density.rs:84` vs `oil/_density.py:159-169`
Rust evaluates the at-Pb density with rsb, Python with rs. With rs != rsb the wheels diverge ~4%, and Rust density is discontinuous at Pb, which the `oil_co` central difference straddles: co near Pb is 1.87e-6/psi on Rust vs 8.37e-6 pure Python (agent reproduction). Pick one semantic, mirror both sides, and make the co stencil one-sided near Pb.

**A8. `make_bot_og` metric Bg column renamed but never converted (~178x)** - `simtools/simtools.py:1858`
gfvf is built in rb/mscf; the metric block relabels to "Bg (rm3/sm3)" without dividing by 178.108 (agent reproduction: 8.515 shown vs 0.0478 true).

**A9. Brine: `salinity_method='sechenov'` and `'auto'` silently apply no salinity in `SoreideWhitson`** - `brine/brine.py:1500-1536, 1782` and `_lib_vle_engine.py:2322, 2348`
The class validates these strings (docstring calls 'sechenov' a legacy alias for gamma_phi) but never maps them; the flash engine only acts on 'gamma_phi'/'explicit'/'embedded', everything else falls through untreated. Agent reproduction: at 20 wt% NaCl, x_CH4 equals the freshwater value for both strings. Map the aliases before the flash call and make `calc_equilibrium` raise on unknown strings.

**A10. Brine: `'embedded'` is a no-op in the flash path** - `_lib_vle_engine.py:599-610, 1932-1934`
For framework='proposed', `get_kij_aq` returns freshwater kij and no gamma is computed, so salinity is dropped entirely (the brine.py:1529 warning text claims a gamma_phi fallback that does not happen). For 'dropin', the delta-kij tables are wired only into the binary path, never the flash; agent measured salting ratio 0.817 vs ~0.24-0.31 expected at 20 wt%.

**A11. Brine: `framework='sw_original'` + default `salinity_method='gamma_phi'` double-counts salting-out** - flash path lacks the binary path's `_SW_GASES_WITH_EMBEDDED_SALINITY` guard
kij is built with embedded salinity AND gamma = 10^(ks m) is applied. Agent measured the combined ratio 0.076 = 0.243 (embedded alone) x 0.31 (gamma alone) at 20 wt%; CH4 solubility ~3x understated out of the box for this framework.

**A12. Spycher 99-109 C blend: weights inverted, and the Python fugacity blend is a no-op via list aliasing** - `brine/brine.py:703-704, 1069, 1108` and `src/spycher_pruess/solubility.rs:114-117`
`blended_val` returns the high-T value at 99 C and the low-T value at 109 C (backwards); confirmed by direct read. Separately, `phiP_ht = self.fugPi` binds the list that `fugP()` then mutates in place, so both blend arguments are identical in Python; Rust copies the array and blends for real, so Python and Rust diverge inside the band (agent: 1.3% xCO2, 4.3% yH2O at 212 F) and are bit-identical outside it. Fix the weights in both languages plus `list(self.fugPi)` in Python.

**A13. Nodal Beggs-Brill: liquid velocity number built with sigma in lbf/ft instead of dyne/cm (11x too large)** - `nodal/nodal.py:1576-1578`, `src/vlp/segment_gas.rs:487-492`, `src/vlp/segment_oil.rs:557-562`
The 1.938 constant requires sigma in dyne/cm (the HB gradient in the same file uses it correctly at nodal.py:924-926). Nlv enters the BB inclination correction; agent measured -32% BHP on a wet gas well and reproduced BHP falling as water rate rises. Confirmed by direct read.

**A14. Nodal Gray: holdup is not the published Gray (1974) correlation** - `nodal.py:1147-1181`, `src/vlp/holdup_gray.rs`
The code's N1 is a Froude group with no surface tension; Gray's N1 is rho_ns^2 vm^4 / (g sigma drho). The R/(R+1) transform is applied twice (lambda_l is passed where R is expected), and the published exponent B is used as an additive term. Confirmed missing sigma by direct read; agent measured 30x holdup overprediction at mist-flow conditions and a condensate-well BHP (1820 psia) far out of family with HB/WG/BB (1077-1209 psia). Verify constants against the Gray paper / API 14B before rewriting.

**A15. `lorenz_2_layers`: arange endpoint bug breaks 28 of nlayers 2-200** - `layer/layer.py:268`
`np.arange(0, 1 + 1/n, 1/n)` with a non-representable step appends a spurious node > 1. Reproduced: nlayers=6 returns 7 layers with mean k 86.1 instead of 6 layers averaging 100, silently. Fix: `np.linspace(0, 1, nlayers + 1)`.

**A16. `oil_matbal` metric mode: Gi term understated by 5.6146x** - `matbal/matbal.py:486, 546-548`
Internal Bg is rb/scf in metric mode and Rp/Rs are converted to scf/stb, but Gi stays in sm3 and multiplies Bg directly. Confirmed by unit-chain derivation (missing factor is exactly SM3_PER_SM3_TO_SCF_PER_STB); agent reproduction shows +34% OOIP on a synthetic metric gas-injection case that recovers exactly in field units.

### Medium severity

Agent measured +2.2% BHP on a high-Fr gas well, plus wrong Payne/inclination treatment for the misclassified pattern.
- **HB two-phase Reynolds constant ~51x too large** (`nodal.py:214, 984`; both Rust segment files): `_HB_RE_K = 96778` vs ~1895 for w in lb/s (2.2e-2 x 86400 published form). Masked in fully rough turbulence; +7% BHP on smooth pipe; the laminar branch is unreachable.
- **`fbhp` returns large negative BHP silently for infeasible injection** (`nodal.py:1781-1782`): only `isfinite` is checked; agent reproduced -238,937 psia through the public API. Floor the march at ~atmospheric and raise.
- **Low-rate gas fallback ignores liquid** (`nodal.py:1213-1220`, Rust x4): below 0.001 MMscf/d the dry static gas column is returned, discarding water/condensate; 3,600 psi discontinuity with 200 bwpd, no warning (the existing warning lives only in the Python path and a different corner).

- **`satdmch4dp` (Eq 4.33) algebra wrong for saline brines** (`brine.py:316-320`): the Sechenov pressure-derivative is lumped into the denominator instead of subtracted; +3.5 to +6% vs the chain-rule derivative of the code's own solubility model (agent analytic + finite-difference). - **Rs mole-basis errors in both brine models** (`brine.py:1346` and `:1905`): Spycher xCO2 is on the ionised basis but converted with paired-NaCl brine moles (Rs -6.7% at 20 wt%); the S&W flash x is salt-free but converted with brine moles (Rs +7.7% at 20 wt%). Exact ratios match the algebra.

- **`oil_deno` returns complex for degf < 60 F on pure-Python wheels** (`_density.py:139-143`): Rust clamps, Python does not; wheels diverge and Python silently returns complex128.
- **`make_bot_og` contract breaches** (`oil/_tables.py:261-262`, `simtools.py:1810`): results["pb"]/["rsb"] return 0 when imputed; sg_sp is overwritten after harmonization so the table violates the user-supplied Rsb slightly.
- **rel_perm_table: sgcr validated but ignored for SGOF; row-count off-by-one in two configurations** (`simtools.py:462, 494-505, 528-569`).
- **`run_all_tests.py` omits `test_errors.py` and `test_rust_acceleration.py`** (the entire parity harness) and could not run them anyway (no pytest delegation). CLAUDE.md says 691 tests; pytest collects 838.

## Part B - Structural findings

### Speed

- **Default `gas_z` array path (DAK or HY with cmethod=PMC, the defaults) loops scalar FFI calls** (`gas.py:1052-1064`): 2.7 ms per 10k points, no faster than pure Python (2.6 ms). Re-routing through the existing `dak_zfactor_batch` with the already-computed tc/pc as user overrides is bit-identical (measured, max abs diff 0.0) and ~2x (1.44 ms). Same for HY. This also fixes the single-sided override divergence for SUT.
- **`validate_pe_inputs` costs ~28 us per all-kwargs call and runs twice per `gas_z`** (entry plus `gas_tc_pc`): ~62% of an 89 us scalar call. A scalar fast path before the numpy machinery would largely remove it. Nodal and oil hot loops are clean (entry-point-only validation).
- **`oil/__init__` eagerly imports pandas, tabulate, gas and brine via `_tables`** (0.35 s to import the oil module for a single scalar correlation), defeating the package's lazy-import design. Move heavy imports inside the functions that use them. `brine.py` likewise imports pandas/tabulate it never uses.
- **`_compute_delta_mp` re-integrates per array element** (`gas.py:296-311`): N independent pseudopressure integrations re-resolving methods each time; one m(p) per unique pressure against a common anchor reuses the work.
- **Honest negatives**: the oil module being scalar-only is not a real cost (full `make_bot_og` with PVTO runs in 0.04 s) - do not vectorise it. `SoreideWhitson._calc_properties` calling `brine_props` 6x per evaluation is tidiness, not performance (~2 ms constructor). Excel library load (412 ms) is once-per-process behind the lazy loader - fine.

### Maintainability

- **The Rust VLP port never received the `_segment_march` scaffold treatment**: `segment_gas.rs` + `segment_oil.rs` carry 8 near-identical march loops (~700 removable lines) and ~70 inline magic numbers, in direct violation of the project's named-constants rule. This duplication is exactly the structure that produced the v3.4.0/v3.5.0 HB constant-drift bugs, and it is where A13 lives four times over.
- **Dead code, ~600+ lines**: `_lib_vle_engine.py` (~450 lines: unused VLE classes, kij variants, superseded fugacity fn, a 120-line `__main__` demo with emoji shipped in the wheel) and `_lib_salting_library.py` (~150 lines: five unrouted ks correlations that docstrings and the Tier-3 doc still describe as live). Smaller items: `_HAMMERSCHMIDT` dict, `_halley_cubic_vec` legacy branch, `gas_cg` unused locals, nodal `_gas_density` both sides, duplicate `_LBFT3_TO_KGM3`, simtools `temp_unit`/`metric_datum_depth`/`got_next`, dead `oil_co` `pi` parameter, `standing = False`.
- **`simtools.py` remains a 2032-line monolith across six unrelated domains.** Natural split mirroring the oil precedent: `_decks`, `_relperm`, `_aquifer`, `_vfp`, `_pvt_tables`. The SWOF/SGOF/SGWFN near-triplicate (~30 lines x3) would have prevented the sgcr and row-count bugs; the VFP formatter prologues and metric save/restore scaffolding are also duplicated.
- **Duplicated brine property chain already drifting**: `brine_props` and `brine_props_co2` re-implement the same Spivey + Mao-Duan chain (~150 lines) and have already diverged (273 vs 273.15, 0.1013 vs 0.1015).
- **Rust-enable flag fragility**: `force_python()` in the parity tests must enumerate nine modules with two spellings (`RUST_AVAILABLE` / `_RUST_AVAILABLE`); a new Rust-dispatching module silently tests Rust against Rust. A single `_accelerator.is_enabled()` accessor read at call time would fix both.
- **CI gaps**: only Windows cp310-cp313 wheels get even an import smoke test (`CIBW_TEST_SKIP` excludes manylinux/macos); the pure-Python wheel is built but never installed or tested; no workflow runs the test suite on push at all (build-wheels.yml is tag-triggered and the only workflow).
- **Doc/context staleness**: `.claude/docs/oil-internals.md` still cites pre-split monolith line numbers; `gas-internals.md` claims HY converges to 5e-4 (see A2) and documents 62.37; `brine-internals.md` lists dead ks correlations as live; Tier-2 brine rule shows `metric=True` defaults that are actually False; simtools rule lists `deck_check` (function is `zip_check_sim_deck`); nodal-internals mislabels nvl as "Eotvos". CLAUDE.md test count (691 vs 838) and the documented PYTHONPATH (`/home/mark/projects` imports a stale ~/.local wheel for ad-hoc commands; should be the repo root) are both wrong.
- **Interactive `input()` paths** remain in `zip_check_sim_deck` and `ix_extract_problem_cells` (default `non_interactive=False` hangs agents); `influence_tables` Python fallback has an unconditional print.
